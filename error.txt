### Final Solution for ClickHouse ✅

#### Approach Tested and Evaluated
1. **Configuration via users.xml file** ❌
   - **Problem**: ClickHouse doesn't easily support customization via mounted XML files
   - **Result**: Abandoned - too complex and non-standard

2. **External initialization script** ❌
   - **Problem**: ClickHouse doesn't use `docker-entrypoint-initdb.d` directory like PostgreSQL
   - **Result**: Abandoned - not supported by ClickHouse

3. **ClickHouse environment variables** ❌
   - **Problem**: ClickHouse only automatically creates user defined in `CLICKHOUSE_USER`
   - **Result**: Abandoned - doesn't allow creating multiple users

#### Final Solution Retained ✅
**`configure_clickhouse()` function integrated into init.sh**

**Advantages**:
- **Robust**: Waits for ClickHouse to be ready (30 max attempts)
- **Intelligent**: Checks user existence before creation
- **Persistent**: Executes on each initialization
- **Non-blocking**: Failure doesn't stop script
- **Maintainable**: Centralized and versioned code

#### Solution Features
1. **Intelligent waiting**: Verifies ClickHouse is ready
2. **Conditional creation**: Creates `clickhouse` user only if it doesn't exist
3. **Automatic permissions**: Grants `GRANT ALL ON default.* TO clickhouse`
4. **Error handling**: Detailed logs and failure management
5. **Clean integration**: Step 11 of initialization script
