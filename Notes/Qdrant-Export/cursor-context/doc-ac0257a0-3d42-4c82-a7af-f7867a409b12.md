52Pi Mini Tower Kit V2 - LED Temperature Control Development (October 26, 2025)

OBJECTIF: Remplacer le binaire moodlight statique par un système de LEDs basé sur la température CPU

COMPOSANTS:
1. Binaire moodlight original (C): /usr/bin/moodlight - matrice 8x8 WS2812B, GPIO 18, couleurs fixes (8 couleurs RGB cyclées)
2. Script Python temp_led.py: contrôle LEDs en fonction température CPU avec gradient de couleur

SOURCE MOODLIGHT:
- Fichier: /home/flowtech/rpi_ws281x/main.c
- GPIO 18, 8x8 matrix (64 LEDs), type GBR, DMA 10
- Effet de chute de couleurs à 15 FPS
- Couleurs définies lignes 146-157: rouge, orange, jaune, vert, bleu clair, bleu, violet, rose

SCRIPT TEMP_LED.PY:
- Fichier créé: /usr/local/minitower/temp_led.py
- Palette: Bleu (froid 35°C) → Vert (40°C) → Jaune (50°C) → Orange (55°C) → Rouge (60°C+)
- Gradient RGB interpolé pour transitions fluides
- Mise à jour: 1 Hz
- Utilise rpi_ws281x (PixelStrip, Color)

PROBLÈME RENCONTRÉ:
- Service minitower_temp_led.service en échec
- Erreur: ModuleNotFoundError: No module named 'rpi_ws281x'
- Cause: module Python installé pour user flowtech mais pas accessible depuis service systemd (root)
- Test: sudo python3 -c "from rpi_ws281x import PixelStrip" → échec
- pip3 install rpi-ws281x bloqué par PEP 668 (externally-managed-environment)

SOLUTIONS POSSIBLES:
1. Installer rpi-ws281x system-wide avec --break-system-packages (risqué)
2. Utiliser virtual environment Python dans service systemd
3. Recompiler depuis source (rpi_ws281x C library + bindings Python)
4. Utiliser le binaire moodlight existant et le modifier en C
