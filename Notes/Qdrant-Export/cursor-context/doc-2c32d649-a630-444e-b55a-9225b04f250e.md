Critical TTL implementation clarification: Qdrant does NOT have native per-point TTL. Recommended approach for DevOps solo: A) Metadata + Cron job purge. Store expires_at in payload, daily cron DELETE with filter expires_at<now(). Single collection cursor-context, no proxy/multiple collections needed for solo use. Metadata schema: type, created_at, expires_at, ttl_days, tags, access_count, last_accessed, promotion_eligible. Python script for purge + promotion automation. 5-phase implementation plan: 2 days initial setup, 2h per phase. Monitoring via Qdrant Dashboard + Python logs. This is production-ready pattern for on-prem vector DB.
