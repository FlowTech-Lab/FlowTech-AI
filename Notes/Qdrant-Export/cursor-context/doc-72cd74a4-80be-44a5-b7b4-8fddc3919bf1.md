MEGA NOTE: COMPLETE MCP QDRANT ARCHITECTURE AND BEST PRACTICES GUIDE

=== MCP QDRANT ARCHITECTURE OVERVIEW ===
Two MCP servers configuration:
- mcp-qdrant-context (port 8000): Session data, read-write, TTL 7 days
- mcp-qdrant-knowledge (port 8001): Permanent base, read-only, documentation

=== WORKING SYNTAX FOR MCP QDRANT ===
✅ CORRECT SYNTAX (ALWAYS WORKS):
mcp_qdrant-context_qdrant-store
  information: "Your text in English"
  # NO metadata parameter needed

mcp_qdrant-knowledge_qdrant-store
  information: "Your documentation"
  metadata: {"type": "documentation", "category": "technical"}

❌ INCORRECT SYNTAX (ALWAYS FAILS):
mcp_qdrant-context_qdrant-store
  information: "Your text"
  metadata: {"key": "value"}  # ERROR: "got string"
  metadata: {}                # ERROR: "got string"
  metadata: null             # ERROR: "got string"

=== CRITICAL RULES ===
1. Context storage MUST be in ENGLISH only
2. NO metadata parameter for context - causes serialization errors
3. Knowledge base supports full metadata
4. Include metadata info in text itself for context
5. Use simple information parameter only for context

=== WORKFLOW FOR AGENTS ===
1. Knowledge first (port 8001) - permanent base, score ≥0.75
2. Context second (port 8000) - session data, score ≥0.70
3. Language: Context=English only, Knowledge=French/English
4. Search strategy: Knowledge d'abord, puis context si besoin

=== TECHNICAL EXPLANATION ===
The metadata parameter issue is a Cursor MCP serialization bug, not a Qdrant limitation:
- Qdrant supports metadata perfectly
- Knowledge base works with metadata
- Context store has serialization bug in Cursor environment
- This is an environment limitation, not a fundamental restriction

=== RECOMMENDED ARCHITECTURE ===
For production pipeline with 6 agents:

1. MCP Context: Text-only storage (workaround for MCP limitation)
2. MCP Knowledge: Full metadata support (works correctly)
3. PostgreSQL: Complex metadata and business logic
4. Redis: Caching layer for frequent queries
5. Qdrant Payload: Vector search with filtering

=== METADATA STRATEGY ===
Context (session data):
- Use structured text in information parameter
- Include metadata in text: [AGENT: 2] [STATUS: completed] [FILE: doc.md]
- No metadata parameter (causes errors)

Knowledge (permanent base):
- Full metadata support
- Payload indexes for filtering
- Complex queries with metadata

PostgreSQL (business logic):
- Source of truth for metadata
- Complex filtering and joins
- Audit trails and history

=== PERFORMANCE OPTIMIZATION ===
Score thresholds:
- Knowledge: ≥0.75 (more strict)
- Context: ≥0.70 (more permissive)

Search strategy:
- Knowledge first for documentation
- Context second for session data
- Combine results if needed

=== TESTED AND CONFIRMED ===
- Context storage: ✅ Works perfectly (without metadata)
- Context search: ✅ Works perfectly
- Knowledge storage: ✅ Works with metadata
- Knowledge search: ✅ Works with metadata
- English language: ✅ Required for context
- French/English: ✅ Supported for knowledge

=== WORKAROUND SOLUTIONS ===
1. Use information parameter only for context storage
2. Include metadata information in the text itself
3. Use PostgreSQL for complex metadata storage
4. Use Qdrant payload indexes for knowledge base
5. Use Redis for caching frequent queries

=== PRODUCTION RECOMMENDATIONS ===
For 50K files/day pipeline:

- Redis: LRU cache (TTL 24h)
