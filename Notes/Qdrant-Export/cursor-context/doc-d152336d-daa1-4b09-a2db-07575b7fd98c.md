RSpec Common Issues and Fixes for Rails 8:

SYNTAX ERRORS IN CONTROLLERS:
- Problem: Special characters (typographic apostrophes) in strings cause syntax errors
- Solution: Use double quotes "..." instead of single quotes '...' for strings with apostrophes
- Example: redirect_to @event, alert: "Impossible d'annuler votre participation."

AUTHENTICATION FAILURES:
- Problem: sign_in helper fails with "Could not find a valid mapping for #<User>"
- Solution: Use post user_session_path instead of sign_in in request specs
- Configuration: Include Devise::Test::IntegrationHelpers in rails_helper.rb

EMAIL NOT SENT IN TESTS:
- Problem: deliver_later enqueues emails, not sent immediately
- Solution: Use perform_enqueued_jobs block to execute enqueued jobs
- Check: ActionMailer::Base.deliveries.count to verify emails sent

DATE FORMAT FAILURES:
- Problem: Date format varies by locale (l() helper not available in tests)
- Solution: Check for year and digits instead of exact format
- Pattern: expect(mail.body.encoded).to include(event.start_at.strftime('%Y'))

PRICE FORMAT FAILURES:
- Problem: Price format varies by locale (10,00 vs 10.00)
- Solution: Check for amount presence instead of exact format
- Pattern: expect(mail.body.encoded).to include('10')

MULTIPART EMAIL TESTING:
- Problem: body.encoded contains base64 encoded content
- Solution: Use decoded body for multipart emails
- Pattern: html_part = mail.body.parts.find { |p| p.content_type.include?('text/html') }
- Pattern: body_content = html_part ? html_part.decoded : mail.body.decoded

MISSING FACTORY TRAITS:
- Problem: Tests use :upcoming trait but it doesn't exist in factory
- Solution: Always define date traits (:upcoming, :past) in factories
- Pattern: trait :upcoming do start_at { 1.week.from_now } end
