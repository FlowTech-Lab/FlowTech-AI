### 🚫 Pièges & bonnes pratiques
- Commits atomiques et messages explicites. Pas de commits fourre-tout.
- Éviter `git add .` aveugle sur gros projets. Préférer fichier par fichier.
- Ne pas réécrire l'historique partagé (`git push --force`) hors cas maîtrisés.
- Toujours `git pull --ff-only` pour éviter des merge non désirés.
- `.gitignore` à jour pour exclure `INPUT`, artefacts, secrets.

### ✅ Checklist express
1. Identité Git configurée et clé SSH testée.
2. `.gitignore` en place avant le premier commit.
3. Commits petits, scopes clairs, anglais.
4. Remote `origin` définie. `main` protégée.
5. Tests et lint avant push.
